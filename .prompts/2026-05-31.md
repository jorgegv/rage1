# Tasks

## Task 1: debug control in ZX

- Previous developments stopped movement working: input seems to be broken for both targets, ZX:
  - make build-minimal and make build: the hero does not move (using QAOP keys). It can shoot, though.

### Resolution

ZX input fixed. Root cause: IN3-3 changed the keyboard defaults to UPPERCASE
ASCII ('Q','A','O','P'); z88dk's in_key_scancode() resolves uppercase letters
through the CAPS-SHIFTed block of its translation table, so QAOP required CAPS
SHIFT and movement was dead while fire (space, unshifted) still worked. Fixed by
using lowercase 'q/a/o/p' in engine/include/rage1/input_zx.h. Verified: hero
moves in JNEXT. (commit 6c14307)


## Task 2: debug control in CPC

- Previous developments stopped movement working: input seems to be broken for both targets, CPC:
  - make build-minimal_audio_cpc: the hero does not move (using QAOP)

### Resolution

CPC minimal_audio_cpc input fixed. Root cause: the game was authored as
minimal_cpc+tracker but DROPPED the `GAME_FUNCTION TYPE=MENU NAME=my_menu_screen`
line, so nothing set controller.type; it stayed CTRL_TYPE_UNDEFINED and
input_state_read() returned NONE. (Audio/PPI was a red herring.) Fixed by
re-adding menu.c + the MENU declaration (commit 0eab58d). Also hardened the
engine: init_controllers() now defaults controller.type to CTRL_TYPE_KEYBOARD so
a game with no MENU function can no longer boot with dead input (commit dfc12b2).
